### A 组：约束与前提

> 有关 A1，我们的浏览器永远会在机主的电脑上，而不是队员自带的设备上

**A3 渲染层数量**

### D 组：传输、状态与安全边界

**D1 传输方式**

> 我可能得看一下。目前可以认定后端已经实现了一个非常闭环的路径，就是通过 TUI 单独渲染。现在主要的问题是，进程似乎是 TUI 跟后端绑定在一起的，不知道有没有办法把它们拆开，或者让 TUI 和 Web 端同时消费后端？不知道这行不行得通。可以认为前端就是消费后端输出的，两者应该不会使用 WebSocket 来通信。

AI 说明：不需要拆进程，见「调研结论」。风险是两者共享事件循环，待 spike 验证。

**D2 状态归属**

> 当然是后端作为唯一真相，前端不存状态，前端只是忠实地反映后端。当然这个也是需要验证的。

**D3 双输入面**

> 我在想能不能让 TUI 和 Web 端在同一个会话中，TUI 跟 Web 的输入都能够同步反映到两边？不知道从技术上来看这行不行。

**D4 中断处理**

> 如果出现了各种各样的中断，就跟在终端里一样处理：比如一个工具正在调用时被中断了，终端怎么处理，Web 端就怎么处理，跟着终端的处理方式走就好。

**D5 回环安全**

> 关于回环安全，我想的是既然 Web 端只是忠实反映后端的一个会话状态，那我觉得没必要上那么严苛的安全检查

## 调研结论

### 降级能力分层（C6）

| 层 | 降级路径 |
|---|---|
| JS 语法 | Vite `build.target` |
| JS 内置 API | plugin-legacy 注入 core-js，代价是双份产物与 SystemJS |
| CSS | Lightning CSS 能转颜色函数与嵌套；`:is()`、`@layer`、容器查询、`aspect-ratio` 只能避开 |
| Tailwind v4、shadcn 当前版 | 无 |
| Tailwind v3.4、React 18 | 可用 |

### pi 扩展能否被 TUI 与 Web 同时消费（D1）

不需要拆进程。同一个内核支持 `tui`/`rpc`/`json`/`print` 四种模式，TUI 只是其中一个消费者；扩展与它同进程，用 `pi.on` 订阅同一份事件流。输入侧同样是多源的：`input` 事件的 `source` 会区分 `interactive`、`rpc`、`extension`，`pi.sendUserMessage()` 发的是真实用户消息，会出现在 TUI 记录里。

### 回退版实测（E1）

本机真跑构建加静态扫描，结论如下。

| 项 | 结论 |
|---|---|
| Tailwind v4 | 硬不可用。产物含 `@layer`，86 会整块丢弃 |
| Tailwind 3.4 | 可用。需补三条 preflight 规则：`abbr`、`button` 与 `input`、`[hidden]` |
| React 18 与 19 | 生产构建都没用到 86 缺的内置方法 |
| Radix 当前版本 | 自己实现了 `at` / `toSorted` / `toReversed`，对 `Array.prototype.at` 有特性检测回退 |
| 未验证 | 真 Chromium 86 实跑（Tim）；shadcn 按 Tailwind 版本发组件（未实测） |

## 事实与依据

| 主题 | 结论 |
|---|---|
| 扩展能力 | 可 import node 内置模块；可起长驻 socket，但须在 `session_start` 起、`session_shutdown` 关；可订阅全部会话与工具事件 |
| 会话数据 | 工具返回的 `details` 会写进 session 文件，刷新可回放；新建与切换会话只在命令上下文可用 |
| 工具约束 | `defaultTools` 只管内置工具，扩展注册的工具不受它约束；`tool_call` 可拦截并拒绝 |
| 运行环境 | 发行版 `pi.exe` 是 SEA，带 node 内置模块，扩展由 jiti 加载 |
| 打包 | 扩展目录整目录进包；发行树检查会扫 JSON 的键名，命中 `token`、`secret` 一类且值非空就报错；文件数直接影响打包耗时 |
| 浏览器基线 | Chromium 86 指 Chrome 86（2020-10）。国内对应 360 安全浏览器 13 与极速 13.x 的内核 |
| 组件生态 | shadcn 当前版要求 Tailwind v4（颜色从 HSL 改 OKLCH），官方称 v3 项目继续发 v3 组件；Recharts 无官方基线 |
| 已作废 | 「Web 进发行版要多带约 85MB Node 运行时」。服务端跑在 pi 进程内，此判断不成立 |
