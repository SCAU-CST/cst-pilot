# PRD — sys 系统检查工具

cst-pilot 的系统检查能力：实时负载 + 配置盘点。
定位：辅助维修人员做软件层面诊断。

## 已有实现

### 诊断工具（自定义）

| 工具 | 状态 | 覆盖 |
|---|---|---|
| `ls`（自定义） | ✅ 已实现 | 目录大小浏览：目录大小、大文件定位 |
| `disk`（自定义） | ✅ 已实现 | 存储分析：磁盘空间 / 信息 / 健康 / 全盘占用扫描 |

### 体验优化（第三方扩展）

| 扩展 | 作用 |
|---|---|
| `open-tui` | 从对话流切换到完整 TUI，交互体验优化 |
| `web-access` | 联网查资料，辅助诊断 |
| `fff` | 高速模糊检索：文件 / 内容 / 历史（frecency） |

### 缺口

存储分析与实时负载（进程 / GPU / 温度）已有（ls / disk / sys 的
proc·gpu·sensor scope）。开机自启盘点（sys 的 startup scope）无工具覆盖。

## 用户与场景

| 用户 | 场景 |
|---|---|
| 维修人员（主） | 上门诊断：机主说"电脑卡"，需要现场定位原因 |
| pi Agent | 调用本工具，把结果转述给维修人员 |

典型提问：

- 谁在吃内存
- CPU 是否被某进程跑满
- GPU 忙不忙、显存够不够
- 温度是否异常
- 什么在开机自启

## 需求

需求分两层：

| 层 | 需求 | 回答 |
|---|---|---|
| 实时负载 | R1–R4 | 此刻发生了什么 |
| 配置盘点 | R5 | 开机时会拉起什么 |

### R1 进程盘点

- 列出内存占用 Top N 进程
- 列出 CPU 占用率 Top N 进程
- 输出进程名、PID、内存、CPU 占用率

### R2 GPU 状态

- 每进程 GPU 利用率
- 每进程显存占用
- 整机 GPU 负载概况
- 有独立显卡时，附显卡温度、功耗、驱动版本

### R3 传感器

- 各硬件温度
- 风扇转速
- 电压

### R4 整机概况

> scope 名 `overview`。内容是整机负载，不是操作系统软件信息。

- 物理内存用量
- CPU 总占用率
- 页面文件状态
- 开机时长

### R5 开机自启盘点

- 注册表自启项
- 启动文件夹自启项
- 自启服务列表

## 非功能需求

| 项 | 要求 |
|---|---|
| 只读 | 不写注册表、不改系统配置 |
| 零宿主安装 | 只用仓库自带运行时，机主电脑不装任何东西 |
| 降级 | 需管理员权限的能力必须可降级：提示 + 其余能力不受影响 |
| 速度 | 单次调用秒级返回，不冻结交互 |
| 输出 | 结构化，便于模型转述 |

## 验收标准

- [ ] R1–R5 各有一致的结果格式
- [ ] 非管理员下：普通能力可用，受限能力给出明确提示
- [ ] 零联网、零安装
- [ ] 结果可被模型直接转述，无需二次加工
